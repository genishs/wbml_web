## 0. 가장 중요한 전제: 버전 번호 매핑 (먼저 읽을 것)

StrategyWiki/GameFAQs의 "Round N" 페이지는 대부분 **SMS 이식판(12라운드)** 기준이다. **아케이드 원판은 11라운드**이며, 차이는 다음과 같다. **[확실]** (StrategyWiki Versions, Sega-16)

- SMS판은 아케이드 **7라운드와 8라운드 사이에 한 라운드(유령 마을/Ghost 보스)를 추가**했다. → 이 추가분(SMS Round 8)은 **아케이드에 없다.**
- 따라서 매핑: **아케이드 R1~R7 = SMS R1~R7** 그대로, **아케이드 R8~R11 = SMS R9~R12**.
- 우리 프로젝트는 **아케이드 11라운드를 정본**으로 한다(game-design.md와 동일 결정).

> 본 문서의 모든 라운드 번호는 **아케이드 번호**다. 공략 자료를 교차 확인할 때는 위 매핑으로 SMS 번호를 환산할 것.

**이 1차 자료가 확정하는 사실:**
- **검 드롭의 정확한 출처 라운드**: 브로드=**2-1(킹 뱀파이어)**, 그레이트=**5-1(자이언트 콩)**, 엑스칼리버=**7-1(코인 컬렉터)**, 레전드/전설의 검=**8-1(데몬)**. (드롭 셀은 "상위단계 검"으로 표기되나, 6R 스핑크스 설명에서 "그레이트 소드 < 엑스칼리버 < 전설의 검" 위계를 명시 → 라운드 순서대로 매핑됨.)
- **R9 보스 = Snow Kong (확정)**. 우리가 임시로 BLUE KNIGHT를 R9에 두었던 것은 **오류**. 블루 나이트는 **7-2 서브보스**이며 10R에 졸개로 재등장. Snow Kong은 자료상 9라운드 메인보스.
- **R10 보스 = Silver Knight (확정)**. 우리의 R10 SNOW KONG 배정은 **오류**(스노우 콩은 9R). Great Catfish/늪 추정은 **근거 없음 → 폐기**.
- **R8 보스 = Demon (확정)**. 우리의 R8 "KING DEMON"은 명칭 과장. 자료 표기는 단순 **Demon**. 레전드 검은 이 데몬(8-1)이 드롭.
- **R2 = 2단 구조**: 킹 뱀파이어(브로드 드롭) + 마이코니드 마스터(열쇠). 우리 stage.js는 R2=MUSHROOM KING 하나로 압축 → 브로드 드롭은 자료상 **마이코니드가 아니라 킹 뱀파이어** 몫.
- **서브스테이지/비밀보스 존재**: 자료는 "비밀 Demon 분기"가 아니라 **각 라운드 내 정규 2단 보스(서브보스)**를 명시(5-2 박쥐, 7-2 블루나이트, 8-2 호브고블린 등). 별도의 "숨은 비밀보스" 항목은 이 자료에 **없음**.
- **R6 스핑크스 퀴즈 정답 힌트표**(자료 명시): 시끄러운 소리=노래하기, 창문 깨짐=골프, 닭 없어짐=덮밥, 다이어트=먹지 않음. 아케이드 꼼수: 기계 리셋 시 정답 3번 고정.

→ **2, 7(부분), 8, 9, 10번이 틀렸다.** game-design.md 2.2 표가 더 정확하나 그것도 일부 추정이 섞여 있다. 아래 라운드별 섹션을 정본으로 삼되, **보스 배정·검 드롭·점수·HP는 위 2.0 표를 최우선**으로 한다.

## 1. 전역 진행 규칙 (모든 라운드 공통)

### 1.1 진행 방향은 라운드마다 다르다 **[확실]**
우리 구현은 **전 라운드 좌→우 고정**이지만, 원작은 그렇지 않다.
- R1, R2 등 초반: **좌→우** (StrategyWiki R1/R2)
- R3: 성 입구 복도를 **우→좌** 로 진행 (StrategyWiki R3 "proceed to the left")
- R4: **우→좌** 진행하며 Baraboro 마을 도달 (StrategyWiki R4)
- R10: 빙굴 **우측에서 좌측 보스문**으로 (StrategyWiki R10)
→ **구현 권고**: 라운드 데이터에 `dir: 'LR' | 'RL'` 필드를 두고 카메라/스폰을 반전. (난도 높으면 최소한 일부 라운드라도 반전 적용)

### 1.2 문(door)과 숨은 문 **[확실]**
- 상점/시설은 **문**으로 들어간다. 문 앞에서 **위(↑) 입력**으로 진입.
- 화면에 **보이는 문**도 있지만, **보이지 않는 숨은 문**이 다수다. 특정 지점에서 ↑를 눌러야 드러난다(특히 후반부 강력 무기/열쇠). (Wikipedia, StrategyWiki Gameplay)
→ **구현 권고**: door에 `hidden: bool` 추가. hidden이면 평소 미표시, 플레이어가 해당 x범위에서 ↑ 누르면 노출+진입.

### 1.3 상점 진열 규칙 **[확실]**
- **방패/갑옷/신발 상점은 "현재 장비보다 위 2단계"를 진열한다.** (StrategyWiki Walkthrough)
  → 우리 `getShopItems`의 `.slice(0,2)` 필터링과 이미 일치. **유지.**
- **무기(검) 상점은 첫 검 Gradius만 판매.** 이후 검은 **보스 처치 드롭**으로만 획득. (Wikipedia, game-design.md) ✓ 현 구현 일치.
- 매직 상점: 폭탄/파이어볼/회오리/썬더. 반복 구매 가능. ✓

### 1.4 시설(비전투 방) **[확실]**
| 시설 | 기능 | 비용 규칙 |
|---|---|---|
| **병원(Hospital)** | 하트 풀 회복 + 모래시계 타이머 리셋 | 숙박할수록 상승: **20 → 40 → 70 → 100 → 110 G** (StrategyWiki Items) |
| **술집/바(Bar/Tavern)** | 드링크로 소량 회복 + **바텐더 힌트** | 드링크 정가 약 15 G; 일부 라운드는 힌트가 공략 필수(R6 스핑크스 답) |
| **NPC/이벤트 방** | 퀘스트(편지·피리·종) 수령/전달 | 무료 |

→ 우리 구현엔 병원/바가 door 타입으로 **없다.** SHOP_TYPE에 `HOSPITAL`, `BAR`, `NPC`(이벤트) 추가 권고.

### 1.5 보스방 & 클리어 **[확실]**
- 필드 끝의 **보스문**을 열고 들어가면 화면 고정 보스방(아레나). ✓ 현 구현 구조 유지 가능.
- 보스 격파 시: **열쇠** 또는 **검 업그레이드** 드롭. 열쇠로 **성문(게이트)** 을 열어 다음 라운드. ✓
- 일부 보스(크라켄 등)는 **재도전 가능** → 열쇠 대신 추가 골드/하트/매직 보상. **[확실]** (StrategyWiki R4)

### 1.6 모래시계 압박 **[확실]**
- 화면 상단 모래시계가 다 떨어지면 하트 1개 감소 후 리셋. 최종 성(R11)에서는 **시간 흐름 자체가 데미지**로 더 가혹. (StrategyWiki R12=아케이드 R11) ✓ game-design.md에 이미 반영.

## 2. 라운드별 구조

각 라운드: **진행 방향 · 톤/지형 · 등장 시설/문 · 숨은 요소 · 보스 · 클리어 흐름** 순. 신뢰도 인라인 표기.

### Round 1 — 마을 입구 / 들판·동굴 입구 (튜토리얼)
- **방향**: 좌→우 **[확실]**
- **톤/지형**: 밝은 초원·푸른 하늘, 동화풍. 작은 단차(ledge)와 떠 있는 블록. **[확실]**
- **진행 흐름** **[확실]** (StrategyWiki R1):
  1. **무기 없이 시작.** 우측 **문 A** 진입 → **첫 검(Gradius) + 회복 물약**(사망 시 부활) 수령.
  2. 문 A 이후 **떠다니는 블록**이 등장 → 타고 다음 플랫폼으로.
  3. 검으로 **뱀(snake)** 처치하며 전진.
  4. 아래로 떨어져 **문 B(바)** 접근 — 이 시점엔 드링크 불필요(돈 아끼기).
  5. 문 B 너머 **첫 코브라(cobra)** — 영역 밟지 말고 찔러 밀어내 처치.
  6. 단차를 올라 **문 C** 도달. 상단 ledge 근처에 **모래시계** 출현(하트 잃기 전 회수).
- **시설/문**: A=무기(첫 검), B=바, C=상점(추정 방패/신발). **[확실/추정]**
- **보스**: **Death(사신/Death Master)** — 낫 든 **비행형**. 튜토리얼 난도. **[확실]**
- **클리어**: 보스 격파 → 열쇠 → 성문. **[확실]**

## 4. 우리 구현 vs 원작 — 차이 분석 & 변경 제안

### 4.1 현 stage.js의 구조적 한계 (핵심)
1. **모든 라운드가 동일 공식**: `fieldLen = 2600 + n*360`, 균등 간격 공중 플랫폼(`x+=350`), 균등 적 배치, 문 5종 일괄 배치. → **라운드마다 똑같은 느낌.** 원작은 라운드마다 지형·구역·문 배치가 전부 다르다.
2. **전 라운드 좌→우 고정** → 원작의 RL 라운드(3·4·10) 미반영.
3. **시설 부재**: 병원/바/NPC가 door 타입에 없음 → 회복 경제·힌트·퀘스트 루프 전체 누락.
4. **숨은 문 개념 없음**: 모든 문이 항상 보임 → 원작의 ↑탐색 재미 없음.
5. **보스 라인업·드롭 오류**(2,7,8,10), 분기(스핑크스 퀴즈/종·루비/비밀 데몬) 없음.
6. **지형 타입 단조**: 물·용암·스프링·떠다니는 블록·구름 플랫폼 등 특수 지형 없음.

### 4.2 구체적 변경 제안 (코드는 차후 dev-lead가 구현)

**(A) 라운드를 "데이터 주도 구역 시퀀스"로 전환**
- 각 라운드를 길이·플랫폼 공식이 아니라 **세그먼트 배열**로 기술:
  ```
  segments: [
    { type:'town',  len:600, doors:[...] },     // 마을: 문 밀집
    { type:'field', len:900, enemies:[...], terrain:'water' },
    { type:'climb', len:500, platforms:[...] }, // 계단/다층
    { type:'bossgate', len:200 }
  ]
  ```
- 마을 세그먼트엔 문(상점/시설) 밀집, 필드엔 적·지형·픽업, 보스게이트는 비움. → 원작의 "마을→필드→보스방" 톤 분할 재현.

**(B) 진행 방향 필드 추가**: 라운드 데이터에 `dir:'LR'|'RL'`. 최소 R3·R4·R10에 `RL` 적용.

**(C) door 모델 확장**:
- `type`에 `hospital`, `bar`, `npc` 추가 + `hidden:bool`.
- 시설 진입 동작: 병원=풀 회복+타이머 리셋(비용 20/40/70/100/110 누진), 바=소량 회복+힌트 텍스트, npc=퀘스트 플래그.
- hidden 문은 해당 x에서 ↑ 입력 시 노출.

**(D) 좌→우(또는 진행축) 길이 가이드**: 균등 공식 버리고 라운드별 **구역 비율**로:
- 마을/문 구간 ≈ 전체의 25%, 필드/전투 ≈ 55%, 보스 직전 여유 ≈ 20%.
- 초반(R1~3)은 짧게(체감 2000~2600px), 후반(R9~11)은 길고 복잡하게(3500~5000px + 분기).

**(E) 상점/문 배치 규칙(원작화)**:
- 무기 문은 **R1에만**(첫 검). 이후 무기 문 ✗(검은 보스 드롭).
- 방패/갑옷/신발 문은 **마을 세그먼트에 1~2개**, 진열은 현행 "+2단계" 유지.
- 매직 문 1개/라운드. 병원은 **거의 매 라운드 1개**(필드 후반), 바는 **힌트가 필요한 라운드(R6 등)에 우선**.
- 후반 라운드는 상점을 **hidden**으로 전환(강력 무기/열쇠).

**(F) 특수 지형 프리미티브 추가**: `water`(낙사/수영), `lava`(접촉 데미지), `spring`(고점프 발판), `floatBlock`(라이드 이동), `cloud`(점프 가능 발판). 라운드별로 선택 사용.

**(G) 보스/분기 정정**:
- 2장 표대로 보스명·드롭 정정.
- R6 스핑크스 퀴즈(3지선다+바 힌트), R10 종/루비 선택, R11 보스 러시+메카 2페이즈, (R7/R8) 비밀 Demon→레전드 소드 분기 구현.
- 크라켄 등 **재도전 보상** 옵션.
