# 아케이드 원작 ROM 분석 (레퍼런스)

> 목적: 원작 **하드웨어 사양·색감**을 파악해 우리 절차적 아트/시스템을 충실히 맞추기 위한 참고.
> ⚠ 저작권: 원작의 **픽셀 그래픽(타일/스프라이트)은 추출·이식하지 않는다.** 우리는 계속 절차적으로 그리며,
> 여기서는 **사실 데이터(하드웨어 구성, 색상값)만** 레퍼런스로 활용한다.

## 식별
- **게임**: Wonder Boy in Monster Land (원더보이 인 몬스터랜드), 아케이드 1987 / SEGA
- **기판**: Sega System 2 계열
- **메인 CPU**: 암호화된 Z80 — Sega **317-0043** (복호 키 `317-0043.key`, 8KB 동봉)
- **사운드**: Z80 + FM/PSG (YM2151 + SN76496 계열)
- **그래픽**: 타일 기반 배경 + 하드웨어 스프라이트

## ROM 맵 (총 16파일, 368KB)
| 파일 | 크기 | 역할(추정) |
|---|---|---|
| `epr11027.86` ~ `epr11030.89` | 각 32KB | 메인 프로그램(암호화 Z80) |
| `ep11031a.90`, `epr11032.91`, `epr11033.92` | 각 32KB | 뱅크 프로그램 / 사운드 |
| `epr11034.4`, `epr11035.5`, `epr11036.6` | 각 32KB | 배경 타일 그래픽 (3bpp) |
| `epr11037.126` | 32KB | 스프라이트 그래픽 |
| `pr11024.8` / `pr11025.14` / `pr11026.20` | 각 256B | **색상 PROM (R / G / B, 4비트)** |
| `pr5317.37` | 256B | Sega 표준 타이밍/주소 PROM |
| `317-0043.key` | 8KB | CPU 복호 키 |

- 프로그램 ROM은 **암호화**되어 있어 평문 문자열 추출 불가(가비지). → 텍스트/수치 직접 추출은 키 복호가 필요.

## 추출한 정품 팔레트
- 색상 PROM 3개(R/G/B, 각 256×4비트)를 디코드 → **256색 팔레트**.
- 4비트(0~15)를 0~255로 스케일(×17). 상위 니블이 모두 0임을 확인 → 정확히 4bpp 색.
- 결과 저장: **`doc/arcade-palette.json`** (256개 hex 색, 유효색 233종).

### 주요 색군 (절차적 아트 매핑 참고)
- **피부톤**: `#cc9988 #ddaa99 #eebbaa #ffccbb` (0x30~0x33)
- **적/빨강**: `#cc0000 #dd0000 #ee0000 #ff0000` (0x4a~0x4d), 주황 `#ff7700~#ffcc00` (0x38~0x3d)
- **녹색**: `#00aa00 #00cc00 #00ff00` (0x55~0x5a)
- **하늘/파랑**: `#0088ff #00aaff #00ccff` (0xa0~0xa4), `#0000cc~#0000ff` (0xce~0xd1)
- **보라/자주**: `#9900cc #aa00dd #cc00ff` (0xd7~0xde)
- **무채색 램프**: `#333~#fff` (0x03~0x0f)

## 활용 방안 (제안 — 결정은 팀/사용자)
1. 절차적 스프라이트의 색상을 위 정품 팔레트 색군으로 **리튜닝** → 색감만으로도 원작 느낌 ↑ (그래픽은 그대로 우리 자작).
2. 향후 키 복호로 **스테이지 구성/적 배치/수치** 등 게임성 데이터 참조 가능(별도 단계).
